# 模板上架流程（Studio）

> 上架包含两个独立阶段：**在模板仓库登记并合并**，以及 **让目标 Studio 环境读取包含该登记的已合并版本**。
> 添加目录、填写 README 表格、运行校验脚本或合并 PR，都不等于模板已在 Studio 画廊显示。

本指南面向模板提交者、PR 审核者和 Studio 测试/发布负责人。清单结构及素材规格以[根 README](../README.md#catalog-source-of-truth)和[预览素材规范](../README.md#gallery-preview-assets)为准。

## 1. 维护边界与完成标准

| 事项 | 维护位置 / 负责人 |
| --- | --- |
| 模板源码、说明、许可、封面和视频 | 本模板仓库 / 模板提交者 |
| 展示标题、描述、分类、顺序、源码目录和素材路径 | 根 [catalog.json](../catalog.json) / 模板提交者与审核者 |
| 格式、路径及媒体检查 | 仓库校验脚本 / 提交者与审核者 |
| 通用加载、渲染、播放、选择和启动 | Studio 应用 |
| 选择已合并版本、更新服务端配置、刷新/重载服务 | 目标 Studio 环境负责人 |
| 真实清单和播放验收 | 提交者与环境负责人共同确认 |

**不要**在 Studio 前端新增逐模板条目、复制素材到其 public 目录，或在模板条目中自行设置 `repo` / `ref`。一个已合并完整 SHA 必须同时决定清单、源码和素材的版本。

“完成上架”需记录：模板 ID、清单变更 PR、所选完整 SHA、目标环境、验收结果。只有仓库提交时，状态应写“已合并，待环境接入”，不要写“已上架”。

## 2. 提交模板目录与说明

从最新 upstream `main` 创建独立短期分支。网站目录为 `sites/<id>/`，App 目录为 `apps/<id>/`。使用小写字母、数字和连字符作为 ID，避免空格、下划线、绝对路径和目录穿越。

网站模板至少包含入口、完整运行资源、模板说明及独立预览素材。例如：

```text
sites/my-template/
├── index.html
├── assets/
├── README.md
└── preview/
    ├── cover.png
    └── video.mp4
```

模板说明应写清启动/构建方式、运行依赖、演示与真实业务的边界、已知限制和许可/署名。App 按其自身说明提交构建资源，并确认 Studio 启动端支持 `apps/<id>`；预览不等于原生设备能力或可安装产物已验证。

## 3. 准备独立封面与视频

新模板以及素材刷新应在同一变更中提交：

- `<dir>/preview/cover.png`：真实、可解码的独立 PNG，不依赖运行时从视频截帧。
- `<dir>/preview/video.mp4`：真实录制的 H.264 MP4，无音轨，启用 faststart（`moov` 在 `mdat` 前）。
- 保持两份素材自身比例，不拉伸；视频建议按 5–30 秒、封面约不超过 1 MiB、视频约不超过 10 MiB 准备。
- 当前校验脚本在 `ffprobe` 可用时会把 5–30 秒范围外的视频判为错误；文件大小超出推荐值仅告警。不要忽略实际退出码，规格调整需同时对齐约定和脚本。
- 存量 GIF/SVG 或无视频豁免仅用于历史兼容，不应把新模板加入豁免来绕过 PNG/MP4 配对规则。
- 素材必须随仓库提交，不使用个人桌面路径、外部视频链接或 Git LFS 指针代替真实文件。

## 4. 在同一个 PR 登记清单

**必须更新根 [catalog.json](../catalog.json)。只增加目录或文档表格不会被画廊自动发现。**

在 `templates` 数组中增加一条，保留已有条目。数组顺序就是展示顺序；使用已有分类，新增分类时同时更新 `scenes`。例如下面的登记仅为示例，提交时替换成真实存在的目录与素材：

```json
{
  "id": "my-template",
  "scene": "tools",
  "title": { "zh": "示例工具", "en": "Example tool" },
  "description": { "zh": "简明说明演示内容及能力边界。", "en": "Describe the demo and its limitations." },
  "dir": "sites/my-template",
  "tone": "ink",
  "cover": "sites/my-template/preview/cover.png",
  "previewVideo": "sites/my-template/preview/video.mp4"
}
```

检查以下内容：

- `schemaVersion` 为 `1`；scene/template ID 唯一，`scene` 引用存在的分类。
- `title.zh` / `title.en` 为非空字符串；建议同时填写双语 `description`。
- `tone` 使用根规范列出的现有枚举；没有逐模板 `repo` 或 `ref`。
- 所有目录/素材路径都是仓库根相对 POSIX 路径，无前导 `/`、`..`、URL 或本机路径；封面/视频位于自己的模板目录且使用上述固定文件名。
- `previewUrl` 可省略；提供时必须是实际公开 HTTPS 演示地址，不是本地服务地址。没有线上 demo 时不要编造链接。
- 分类、文案、顺序、说明与展示素材相互一致；更新旧模板时仍需遵守素材刷新约定。

## 5. 运行校验，理解其覆盖范围

校验脚本必须已经包含在当前工作树中。如果脚本变更尚未合并或整合到提交分支，先完成该前置条件，不能把“命令找不到”当作校验通过。

在模板仓库根目录运行：

```bash
test -f scripts/validate-catalog.py
python3 scripts/validate-catalog.py
```

脚本退出码 `0` 表示**其已执行的检查**没有错误；退出码 `1` 或运行异常需先修复再提交。审查全部 `WARN`，不要只看最后一行。

### 当前脚本能检查什么

- 主要清单字段、唯一 ID、分类引用、双语标题存在及配色枚举。
- 已登记路径是否存在、路径是否满足其根相对检查、模板入口是否存在。
- PNG 文件签名、媒体大小告警、MP4 atom 顺序；有 `ffprobe` 时检查 H.264、音轨和时长。
- 新条目必须声明封面与视频；历史豁免保持兼容。
- `previewUrl` 的 HTTPS 前缀。

### 不能把脚本通过理解为什么

- **不是目录自动登记。** 当前脚本遍历已有清单条目，不会自动把新目录加入清单，也不能拦住“目录已新增但清单漏登记”。提交者和审核者必须逐个对照新增目录与清单。
- **不是完整媒体检查。** `ffprobe` 缺失或失败时，编解码、音轨和时长检查会跳过并告警，脚本仍可能返回 `0`。新/更新视频需在有 `ffprobe` 的机器上补验；PNG 签名也不等于完整解码或画面正确。
- **不是完整消费者兼容证明。** Studio 的字段类型、ID/目录格式、固定素材路径等读取约束仍需核对；HTTPS 前缀检查不证明地址在公网可达。
- **不是自动 CI 或自动发布。** 添加脚本文件不等于已经接入 PR CI，也不等于必须通过的分支保护检查。若目标仓库已配置 CI，再确认该检查实际执行并成功；否则在 PR 中记录本地命令、退出码和告警处理。
- **不是页面验收。** 运行资源、依赖、真实浏览器解码、画面、交互与许可边界需要另外检查。

可用下列命令辅助审查变更与清单 ID；其中 `origin/main` 应换成你实际的 upstream 主分支引用：

```bash
git diff --name-only origin/main...HEAD
python3 -c "import json; c=json.load(open('catalog.json', encoding='utf-8')); print([t['id'] for t in c['templates']])"
```

视频可在安装了 `ffprobe` 的环境补验：

```bash
ffprobe -v error -show_streams -show_format -of json sites/my-template/preview/video.mp4
```

记录输出中的 `codec_name=h264`、没有 audio stream、时长符合要求，以及校验脚本的 faststart 检查。示例路径必须替换为待上架模板路径。

## 6. 提交、审核并合并 PR

PR 应同时包含源码/素材、清单登记和必要说明；仅修改现有登记或文档时明确缩小范围。审核清单：

- [ ] 每个待上架的新目录均已登记，未漏掉只出现在文档表格中的模板。
- [ ] ID、分类、双语文案、排序和能力描述准确；已有条目没有被意外替换。
- [ ] 所有引用路径存在，PNG/MP4 配对、真实解码及媒体检查完成。
- [ ] 校验命令、退出码、WARN 的处理及浏览器检查结果已记录。
- [ ] 模板依赖、演示限制和许可/署名说明完整。
- [ ] 合并后接入环境与负责人明确，没有承诺“合并即自动上架”。

提交并经审核合并到 upstream `main`。不自动合并 PR，不把未合并分支当成正式清单，不通过复制素材到 Studio 前端规避仓库发布流程。

## 7. 选择已合并版本并更新目标环境

由目标 Studio 环境负责人执行。先获取 upstream `main` 的候选完整 SHA，避免误用个人 fork 的落后主分支：

```bash
git fetch https://github.com/stepfun-studio/studio-template.git main
git rev-parse FETCH_HEAD
```

输出应是完整 40 位 commit SHA，不能直接将 `main`、PR 分支、短 SHA 或未合并提交填入配置。确认该提交已经包含**目标清单登记、源码和全部素材**；如有相关校验/文档变更也应已整合。使用旧的已合并版本是允许的，但新模板不会因此出现在画廊。

在 **Studio 服务端环境**设置，而不是在本模板仓库或浏览器中设置：

```dotenv
STUDIO_TEMPLATE_REF=<已经合并且包含目标清单的完整40位SHA>
```

按目标环境的配置流程更新，并刷新/热重载或重启原服务，确认新配置实际生效。不要启动一个无关端口的替代服务来验证原测试页面。国内/海外、本地测试/部署测试/生产是不同环境，需要分别确认；更新本地配置不等于更新已部署服务。

生产更新遵守对应审批与部署流程。本指南不授权执行部署。清单、源码和素材始终使用同一个固定 SHA；不单独修改媒体 URL 指向另一个版本，不把缺失配置或读取失败回退为前端内置清单。

## 8. 用真实仓库数据完成验收

在目标环境的真实 Studio URL 刷新页面并确认：

- [ ] 读取的是本次配置的 SHA，新模板 ID、标题、分类和顺序正确。
- [ ] 所有封面从该提交真实加载；空闲时静态展示、无意外自动播放。
- [ ] hover / 键盘聚焦视频静音、内联播放；离开后停止。
- [ ] 详情弹窗与选中后的输入框预览正常播放；关闭/移除后停止。
- [ ] 视频失败时回退到独立封面，不影响直接开始对话。
- [ ] 通过测试或已授权的启动验收核对标记，确认源码版本与素材/清单版本一致；实际发起任务应另有授权。
- [ ] 旧模板、旧 GIF/SVG 和未知历史模板标记未出现兼容性回归。

PR 合并前可以使用明确标注的受控浏览器 fixture 验证待提交清单，但不能因此宣称真实环境已发布，也不能把未合并 PR 配置为正式版本。最终上架验收必须使用已合并仓库的真实清单与媒体。

## 9. 常见问题与回退

| 现象 | 优先检查 |
| --- | --- |
| 新目录已合并，但模板没出现 | 目录是否登记在根清单；当前固定 SHA 是否包含该登记；是否选中了排除它的分类 |
| 校验通过，但新增目录不显示 | 脚本不会发现漏登记的目录；手工对照新增目录和清单，再检查环境版本 |
| 出现“模板加载失败” | 服务端变量是否缺失/格式错误、该 SHA 是否包含清单、仓库网络/HTTP 状态、清单是否被消费者拒绝 |
| 文案已更新，但仍看到旧内容 | 是否只修改 README 表格、目标环境是否仍读取旧 SHA、服务配置与页面是否刷新 |
| 封面正常，视频失败 | 文件是否真实 MP4、编解码/音轨/faststart、网络与浏览器播放状态；保留封面回退 |
| 一个测试环境正常，另一个仍旧 | 国内/海外或本地/部署服务是否分别更新了配置 |

出现回归时，按环境授权流程把 `STUDIO_TEMPLATE_REF` 恢复为记录过的上一完整已合并 SHA，重载原服务并复验。无需重写前端清单或恢复素材副本；修复在模板仓库另开 PR，审核合并后再切换版本。
